# RustWay 知识点加载规范（对外发布版）

> 你只需要写一个 JSON 文件，就可以向 RustWay 贡献知识点。
> 本规范是机器可校验的契约：schema 定义见 [`schema/kp.schema.json`](../schema/kp.schema.json)（单个知识点）与 [`schema/kp-file.schema.json`](../schema/kp-file.schema.json)（提交文件格式），也可通过运行中的服务访问 `GET /api/schema` 获取。

## 一、最简可用示例

```json
{
  "kps": [
    {
      "id": "kx-9-1",
      "title": "示例知识点",
      "difficulty": 1,
      "minutes": 30,
      "summary": "一句话概述：学完这个知识点你能做什么。",
      "task": "实现 X 并通过给定测试；运行 Y 命令观察 Z 输出，确认与预期一致。",
      "refs": [
        { "t": "官方文档", "u": "https://doc.rust-lang.org/" }
      ],
      "quiz": [
        {
          "q": "题干必须独立可答（先答后看）？",
          "opts": ["错误项", "正确项", "干扰项", "干扰项"],
          "answer": 1,
          "why": "解析：为什么 B 对，其他项错在哪。"
        }
      ],
      "tags": ["示例", "入门"],
      "prereqs": [],
      "author": "your-github-name"
    }
  ]
}
```

顶层固定为 `{ "kps": [ … ] }`，一个文件可以放任意多个知识点。

## 二、字段规范

### 必填字段

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | string | `^[a-z0-9][a-z0-9-]*$`，≤32 字符 | 全局唯一。建议 `k<模块><章><序>`（如 `k1-3-1`） |
| `title` | string | 2–40 字符 | 标题：简短、可搜索、独立成义 |
| `difficulty` | int | `1` / `2` / `3` | 入门 / 中阶 / 进阶，对应 ★☆☆ ★★☆ ★★★ |
| `minutes` | int | 5–600 | 预计学习分钟数（含验证任务） |
| `summary` | string | 8–80 字符 | 一句话概述；独立成句，显示在图谱提示与卡片 |
| `task` | string | ≥20 字符 | **动手验证任务**：写清「做什么 + 如何客观确认做对了」，须在终端/测试中可完成 |
| `refs` | array | ≥1 条 | 引用出处。优先官方文档 > 权威教材 > 论文；链接必须可访问 |
| `quiz` | array | ≥1 题 | 自测题（见下） |

### `refs[]` 条目

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `t` | ✔ | 出处标题，≥4 字符 |
| `u` | ✔ | `http(s)://` 链接 |

### `quiz[]` 条目（测试用例）

| 字段 | 必填 | 约束 |
| --- | --- | --- |
| `q` | ✔ | 题干 ≥8 字符，**独立可答**（读者不看正文也能做） |
| `opts` | ✔ | 2–6 个选项 |
| `answer` | ✔ | 正确项下标（0 起），必须 `< opts.length` |
| `why` | ✔ | 解析：说清「为什么对、错误项错在哪」 |

测验即测试用例：读者答对本知识点全部题目会自动点亮「已掌握」状态；题目质量决定掌握判定的可信度。

### 选填字段

| 字段 | 说明 |
| --- | --- |
| `prereqs` | 前置知识点 id 数组。必须已存在；服务端用 Kahn 算法保证整张前置图**无环**。宁多勿漏——依赖链的诚实度决定图谱导航价值 |
| `outline` | 要点数组（≥2 条）。无详细文档时作为页面正文展示 |
| `detail_md` | 详细讲解 Markdown 路径（`content/…md`，相对仓库根），文件须随提交给出 |
| `tags` | ≤5 个。**相似算法权重最高的语义锚点**：新节点即使不声明前置，也会按标签/标题/摘要的余弦相似度自动接入图中最相关的节点 |
| `author` | 你的 GitHub 用户名（收集阶段归属记录） |

## 三、知识之间的关联如何建立

1. **手工前置**（`prereqs`）：强依赖、有先后学习顺序的关系，由作者声明；
2. **算法相似**（自动）：服务端对所有知识点做加权分词（tags×4、title×3、summary/outline×1）+ 余弦相似度，每节点自动连接 top-3 相似邻居（阈值 0.16）。前端图谱中前置为实线灰边，相似关联为紫色细边，可分别开关。

因此：**即使你不写任何 `prereqs`，新知识点也会被相似算法接入图中最相关的位置**；但强顺序依赖请务必手工声明。

## 四、提交与自检流程

```bash
# 方式 A：命令行自检（推荐，秒级）
cargo run -- import your-kps.json      # 沙箱全量校验，不改动正式内容

# 方式 B：放进正式目录后全量验证
cp your-kps.json content/kps/          # 文件名任意；下划线开头 = 草稿不发布
cargo run -- validate                  # 结构 + 完整性规则
cargo test                             # 与 CI 同款门禁

# 方式 C：不看仓库，仅校验 JSON 结构
cargo run -- schema > kp-file.schema.json   # 取回 schema 后用任意 JSON Schema 校验器
```

通过后提交 Pull Request，或直接把 JSON 文件发给维护者。

## 五、机器强制的规则（违反即拒绝）

1. `id` 全局唯一；一个知识点只编入一个章节
2. `prereqs` 引用必须存在；前置图无环
3. `refs` 非空且全部为 http(s) 链接
4. `quiz` 非空；`answer` 不越界；每题有解析
5. `difficulty ∈ {1,2,3}`；`detail_md` 指向的文件必须存在
6. 课程骨架规模下限不可被意外删减

警告类（不拒绝，建议修复）：图谱孤岛节点、摘要过长、`minutes` 超范围、重复引用等。

## 六、章节编排（可选）

新知识点默认进入网站首页的「待编排」区（不影响使用与图谱展示）。
若要编入学习路径，在 `content/curriculum.json` 中把 `id` 插入目标章节的 `kps` 数组——**数组位置即学习顺序**，支持任意位置插入。
