# 注释与文档注释

> 对应知识点：k1-1-1 · 预计 15 分钟 · 难度 ★☆☆

## 学习目标

- 区分 `//`、`///`、`//!` 三种注释的用途
- 写出带示例代码块的文档注释并用 cargo doc 验证

## 一、三种注释

```rust
//! 模块级文档：写在文件/模块顶部，描述"这一整个文件是什么"。
//! （对本文件 crate 根而言，描述整个 crate。）

// 普通行注释：给读代码的人解释"为什么这么写"。

/// 条目文档注释：写在函数、结构体、字段等条目的**上方**，
/// 会出现在 rustdoc 生成的 API 文档里。
fn add(a: i32, b: i32) -> i32 {
    a + b
}
```

记忆口诀：`//` 说话给同行，`///` 说话给使用者，`//!` 说话给整个文件的读者。

## 二、文档注释里的示例即测试

````rust
/// 把两个数相加。
///
/// # Examples
///
/// ```
/// let result = mylib::add(2, 3);
/// assert_eq!(result, 5);
/// ```
pub fn add(a: i32, b: i32) -> i32 {
    a + b
}
````

关键认知：`cargo test` 会把每个 ``` 代码块**编译并运行**（k4-2-2 详述）。所以文档示例永远不会腐烂——API 变了、示例没改，测试直接红。

常用代码块标注：

| 标注 | 行为 | 用途 |
| --- | --- | --- |
| （无） | 编译 + 运行 | 展示正确用法并可验证结果 |
| `no_run` | 只编译不运行 | 涉及网络/文件等副作用 |
| `compile_fail` | 断言**不能**编译 | 证明某误用会被编译器拒绝 |
| `ignore` | 完全跳过 | 伪代码占位（尽量少用） |
| `text` | 纯文本 | 输出示例、命令行 |

## 三、注释写什么

好注释解释**为什么**，坏注释复述**是什么**：

```rust
// 坏：i 加一
i += 1;

// 好：接口限流要求请求间隔 ≥ 100ms，见 issue #42
thread::sleep(Duration::from_millis(100));
```

TODO/FIXME 前缀有惯例含义：`TODO(名字)` 表示待办且负责人明确，`FIXME` 表示已知缺陷待修。

## 四、动手实验

1. 给 `add` 加上文档注释与示例代码块
2. 运行 `cargo doc --open`，在浏览器中找到它并确认示例展示正常
3. 故意把示例写成 `assert_eq!(add(2, 3), 6)`，运行 `cargo test` 观察文档测试失败

## 常见误区

| 误区 | 事实 |
| --- | --- |
| 用注释"注销"大段代码留在仓库 | 删掉——git 历史里都有；死代码误导读者 |
| 文档注释写满实现细节 | 文档面向使用者，写契约与示例；实现细节用普通注释 |
| `///` 和 `//` 混用位置随意 | `///` 位置错误（如函数内部）会被当普通注释或报错 |
